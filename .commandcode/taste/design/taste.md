# Design taste

- Prefers a professional, minimal, restrained industrial/enterprise dashboard aesthetic (internal enterprise tool like a SCADA/monitoring console) over flashy or playful consumer-app styling. Confidence: 0.9
- Prefers muted dark navy/slate color palettes with a single accent color (teal or blue) used for active states and success indicators; red/amber reserved strictly for warnings and errors. Confidence: 0.9
- Prefers clean typography, clear data hierarchy, and restrained motion — no gradients-everywhere or bouncy animations; animation used only for meaningful state changes (e.g., staggered reveal of processing steps). Confidence: 0.85
- Prefers visible, text-labeled controls for important/critical actions (e.g., a labeled "Sign out" button) over icon-only affordances, which are easy to miss and get reported as missing functionality. Confidence: 0.65
- Wants theme/UI features (e.g., light mode) to be applied completely and consistently across every screen and component ("properly apply light colors everywhere"), not just the header toggle — partial application that leaves isolated dark panels, blue-tinted surfaces, or low-contrast text is treated as incomplete and reported back as a bug. Confidence: 0.95
- Light mode should be pure white (#ffffff) across all major surfaces — root canvas, landing page, sidebar, and panels — not a pale blue/slate tint anywhere; only subtle neutral light grays are acceptable for hover states and separators, with teal reserved for accents/active/success states. Confidence: 0.9
- Expects conversation history sidebar to be grouped chronologically (Today / Yesterday / Older) with management actions: create new conversation, rename, search, delete/archive, and continue/resume old conversations. Confidence: 0.9
- Prefers reusing the established left-list → click → workspace-detail pattern across modules for consistency (explicitly asked to apply the same conversation-history sidebar + workspace handoff flow to the Model Registry). Confidence: 0.82
